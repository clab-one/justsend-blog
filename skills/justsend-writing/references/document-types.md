# Document Type Routing

| 유형 | 독자 질문 | 필수 흐름 |
| --- | --- | --- |
| engineering-story | 무엇을 왜 바꾸고 무엇을 배웠나 | 맥락 → 제약 → 시도 → 결정 → 결과 → 남은 과제 |
| architecture-decision | 어떤 선택지를 왜 골랐나 | 문제 → 결정 기준 → 대안 → 결정 → 결과 |
| explanation | 이 시스템은 왜 이렇게 동작하나 | 독자 가치 → 개념 → 동작 → 경계 → 예시 |
| incident-review | 무엇이 실패했고 재발을 어떻게 막나 | 영향 → timeline → 원인 → 대응 → 방지책 |
| tutorial | 처음부터 성공 경험을 어떻게 얻나 | 목표 → 준비 → 단계 → 확인 → 다음 학습 |
| how-to | 특정 결과를 어떻게 얻나 | 조건 → 절차 → 성공 확인 → 오류 복구 |
| reference | 정확한 계약을 어디서 찾나 | 범위 → signature/options → behavior → examples |
| product-narrative | 사용자 문제를 제품이 어떻게 푸나 | 사용자 맥락 → 문제 → 접근 → 가치 → 제약 |
| launch-post | 무엇이 출시됐고 누가 왜 써야 하나 | 가치 → 대상 → 핵심 변화 → 사용법 → 제한 |

복합 성격이면 독자의 주된 목표 하나를 primary type으로 정하고 보조 유형은 section 수준에서만 사용한다.
