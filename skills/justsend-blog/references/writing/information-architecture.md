# Reader-first Information Architecture

- 첫 화면에서 독자, 변화, 읽을 가치를 식별할 수 있어야 한다.
- 기능 목록보다 독자가 해결할 문제와 판단할 trade-off를 먼저 쓴다.
- 각 section의 purpose는 하나의 동사로 표현한다: 설명한다, 비교한다, 검증한다.
- heading은 구체적인 명사와 결과를 포함하고 같은 문법 패턴을 유지한다.
- 배경은 이후 결정을 이해하는 데 필요한 만큼만 제공한다.
- 시간 흐름, 시스템 흐름, 의사결정 흐름을 한 section에서 섞지 않는다.
- detail은 핵심 결론 뒤에 둔다. 독자가 예측 가능한 순서로 깊이를 높인다.
- 관련 Evidence가 없는 side story는 분리하지 않고 삭제한다.
